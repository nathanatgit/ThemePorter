A fix release for 1.3.

## Picking an icon for Gallery now works

Choosing an icon for **Gallery** under Manual replacement had no effect: the built theme kept showing the icon pack's own gallery artwork instead of the one picked.

An app can be written into a theme under more than one name — the name ZTE's stock themes use, the name of the activity your phone actually exposes, and the package on its own. Assigning an icon only claimed the first, while the pack's own artwork for the same package filled the other two, so the app answered to three files holding different pictures and the chosen one was not what appeared.

Gallery was the only system app this could affect, because `com.android.gallery3d` is the only one of these packages that icon packs also ship their own artwork for — which is why every other system app took its manual icon correctly.

Stock themes name a system app with exactly one file, so assigning an icon now reserves that package and the theme carries the single stock-named file, exactly as a stock theme does. Phone and Contacts share `com.android.contacts`, where one file could only ever show one of the two, so those are left as they were.

## System apps with no artwork are no longer blank

A system app the icon pack has no artwork for showed an empty cell, with nothing to preview, select or put a tone curve on — on a nubia Z70 Ultra that was AI Assistant, Compass and Community. Those cells now fall back to the app's own launcher icon and go through the same shape, tint and curve pipeline as everything else, which is what app cells further down the screen already did.

## Also

The theme format notes now record why a system app has to answer to exactly one file, including what was tried and did not work, so the reasoning is not lost.
